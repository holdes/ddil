02 · Kit configuration runbookKnown issues
Read first

Known issues as of 13 Nov 2026.

These items come from the committed code at 5114c3a. The kit may already carry local fixes. Check each item on the kit and record what you find.

Known issues as of 13 Nov 2026

K1 · Showcase target: Elastic 9.5.6 on every node

The kit showcases Elasticsearch and Kibana 9.5.6 with one security configuration. Change from the committed pins: es-gpu 9.4.2 with security and transport TLS on; es-cpu 9.3.1 and Kibana 9.3.1 with security off. Fix: page 13. Check: _cat/nodes lists spark-gpu and framework-cpu on 9.5.6 (page 6).

K2 · The backend container has no Elasticsearch credentials

Compose sets no VINEYARD_ES_USER or VINEYARD_ES_PASSWORD, has no env_file, and .env is excluded from the image. Every backend call to the secured node returns 401. Vineyard screens then show fallback numbers with no error; SEC and Multimodal show errors. Fix options (not yet in the repo): add both variables to the backend environment in demo/docker-compose.yml, or run the backend natively with demo/backend/run.sh, which reads demo/backend/.env.

K3 · Showcase model lineup: Nemotron 3.5 Lightning and Jina v5 Omni

The kit showcases NVIDIA Nemotron 3.5 Lightning and Jina Embeddings v5 Omni. Change from the committed config: gpt-oss:120b, nomic-embed-text, EMBED_BACKEND=bedrock and the serve_jina_v4.py server. .env.airgapped is not read inside the container, so set values in the compose environment. The SEC code on this branch embeds queries with Jina v5 Omni (EMBED_BACKEND=jina, 768 dims) and the SEC index must be re-embedded to match (page 14). With the Jina server down, SEC Chapter 03 search returns 502 "Query embed failed". Fix: page 14. Check: /api/finance/agent/state.

K4 · The .ddil names are untested on the box

Commit 5114c3a switched backend defaults to es.ddil, ollama.ddil, jina.ddil and kibana.ddil while the app was not running. If resolution fails, every cross-host call fails. Check from inside the backend container (page 6). Fallback: set the URL variables to raw IP addresses.

K5 · Stale TROUBLESHOOTING.md step deletes the model

The "Unload unused models" step calls Ollama DELETE /api/delete. That call deletes the model from disk. Re-pulling nemotron-3.5-lightning needs an internet connection the kit does not have. Never run it. The same file names containers, ports and models that the kit does not use. Use it only for generic Elasticsearch fixes (memlock, vm.max_map_count, allocation explain).

Also note

  • run-all.sh passes only EP; setup-index-local.sh also needs ES_USER and ES_PASSWORD. setup-indices.sh, bulk-index-synthetic.sh and race.sh send no credentials at all.
  • After the 9.5.6 upgrade, run one Agent Builder converse/async question end to end before a show.
  • scripts/ddil-startup.sh checks raw IPs without auth and probes Ollama on .10. Its health banner is stale.

The repo does not document a power-on order. This order follows the service dependencies: the backend on the Framework calls Elasticsearch, Ollama and the Jina server on the Spark, and the two ES nodes discover each other on :9300.

02 · Kit configuration runbookBring-up on the DGX Spark
Bring-up · DGX Spark (192.168.1.20)

Elasticsearch, Ollama and the Jina server.

Start Elasticsearch (es-gpu)

cd ~/ddil/docker
sg docker -c "docker compose up -d"

No repo script pulls the model. Pull it with ollama pull nemotron-3.5-lightning while connected (page 14). If it is missing, the kit cannot run the adventures until the model is copied in from a connected machine.

Start the Jina Embeddings v5 Omni server

# in a tmux or screen session so it survives logout
conda activate jina-embed
# serve jinaai/jina-embeddings-v5-omni-small on 0.0.0.0:8081; launch command: confirm on kit (page 14)

There is no systemd unit for the Jina server. It must be started by hand after every boot. GET :8081/health reports the loaded model; it must name jina-embeddings-v5-omni-small.

Kiosk on the touchscreen

The kiosk is a separate app on port 3100, served by systemd units on the Framework. Its health page uses mock data while MOCK = true in demo/kiosk/src/lib/health.ts, which is the committed default. A green kiosk does not prove the services are up. Use the checks on the next page.

Applying environment changes to the backend

The backend reads VINEYARD_* variables from its process environment. In the container, only the environment block of the backend service in demo/docker-compose.yml reaches it. After editing that block, recreate the container:

docker compose up -d --force-recreate backend
curl -s http://192.168.1.10:8000/api/finance/agent/state

Variable names are on page 9. Do not commit secret values to the repo.

Reset between demos

Return to the chooser in a known state.

The adventures read data and do not write it, so a reset is a front-end and session reset. No index needs to be restored between audiences.

Shutdown

Reverse order: Framework, then Spark, then network

# Framework Desktop
cd ~/ddil/demo && docker compose down
sudo shutdown -h now

# DGX Spark: stop the Jina server with Ctrl-C in its session, then
cd ~/ddil/docker && sg docker -c "docker compose down"
sudo shutdown -h now

# Then power off the switch and the gateway
Never by habit

docker compose down -v also removes the compose volumes, which can hold index data. Use it only when you intend to wipe and re-provision. Never run the Ollama "unload" step from TROUBLESHOOTING.md (K5).
