In one paragraph

The DGX Spark runs the GPU Elasticsearch node with cuVS, vLLM with NVIDIA Nemotron 3.5 Lightning, Ollama, and the Jina Embeddings v5 Omni server. The Framework Desktop runs the CPU Elasticsearch node, Kibana with Agent Builder, the FastAPI backend and the React frontend in Docker. The backend sends every adventure query to the Spark node.

Read with care

Where the committed configuration is inconsistent, this guide states what the code does and marks it "current state, verify on the kit". Page 3 lists those items.

NVIDIA describes Nemotron 3.5 Lightning as an open-weight mixture-of-experts model in the NVIDIA NeMo family: about 30B parameters with about 3B active, hybrid Mamba-2 and attention layers, built for long-running agentic workloads. Licence OpenMDW-1.1, commercial use permitted. Jina Embeddings v5 Omni places text and images in one vector space. Jina is part of Elastic.

Jina embedding server contract

  • POST /v1/embeddings with {input: [text or {type: "image_base64", ...}], dimensions?}. Response is OpenAI shaped. GET /health for status.
  • The ES inference endpoint, jina-multimodal and SEC request 768 dimensions. Need-to-Know sends no dimensions and takes the server default, 1024. Confirm the server default on the kit.
  • Callers send model name jina-embeddings-v5-omni-small.

01 · Architecture guideData flow per adventure
Data flow

How one request travels through the kit.

Every flow starts in the browser at http://192.168.1.10:3000. The Vite server proxies /api to the backend on port 8000. The backend sends all adventure queries to es.ddil:9200, the Spark node.

Vineyard · AI Agronomist
  1. POST /api/chat/agent/stream opens an SSE stream.
  2. Phase 0: latest vineyard-soil and vineyard-npk doc for the block, or across all blocks when no block is passed.
  3. Phase 1: kNN on 8-dim reading_vector, k=5, num_candidates 100, filtered to the block. Then an LLM call.
  4. Phases 2, 3, 4: risk, recommendation, action plan. One LLM call each, in sequence.
  5. Each LLM call: vLLM /v1/chat/completions, Nemotron 3.5 Lightning, temperature 0.1, 120 s timeout.
SEC · Search and agent
  1. Search: the backend embeds the query with Jina Embeddings v5 Omni on the Spark (768-dim).
  2. kNN on emb in sec_10k_2026, k=8 by default, optional sector filter. Hits and took_ms return to the UI.
  3. Agent: the backend posts to Kibana /api/agent_builder/converse/async with the input, agent id and connector id.
  4. Agent Builder runs finance-analyst. Tools run ES|QL on the cluster. The connector calls Nemotron 3.5 Lightning on vLLM.
  5. Kibana streams events back. The backend relays them unchanged.
Multimodal · Search by Image
  1. GET /api/jina/multimodal/search?q&space.
  2. The backend sends one kNN with query_vector_builder, model jina-omni-text, on image_vector or caption_vector, k=6.
  3. Elasticsearch calls the inference endpoint, which calls the Jina server for a 768-dim query vector.
Multimodal · Need-to-Know
  1. The backend builds the clearance filter for the selected persona.
  2. It embeds the question on the Jina server (1024-dim).
  3. RRF of BM25 on content and kNN on embedding (k=50, 200 candidates) with the filter, collapsed on parent_id, top 6.
  4. Passages, capped at 1,200 characters, go to Nemotron 3.5 Lightning with a prompt that forbids outside knowledge.
