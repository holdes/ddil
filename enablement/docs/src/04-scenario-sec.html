SEC Findings. An Elastic agent on the edge.

Presenter runbook for the SEC Findings deck: audience, story, pre-show checks, a timed click path through all chapters, exact prompts, likely questions, failure recovery and reset.

Suggested length 15 to 20 minutes Status as of 13 Nov 2026 Code basis: commit 5114c3a
Audience and outcome

For analysts, research teams and AI platform owners who want agentic search over large document sets without sending documents or prompts to a cloud model.

They leave knowing that semantic search and an Elastic Agent Builder agent with ES|QL tools run on the kit, answer comparative questions across S&P 500 10-K filings, and cite their sources.

The story in three sentences

Risk disclosures in annual 10-K filings take an analyst hours to read and compare.

On the kit, Elasticsearch searches the filings by meaning, and an Agent Builder agent uses ES|QL tools to compare companies and sectors, with NVIDIA Nemotron 3.5 Lightning as its model.

The opening chapters race the kit's two nodes, GPU against CPU, as the reason the approach scales; the race is a simulation, and nothing in the deck carries a cloud bill.

Keyboard

Right arrow or PageDown: next. Left arrow or PageUp: previous. Digits 0 to 5 jump to chapters 00 to 05. The two segues are reachable only by arrows or a chip click. Esc exits to the chooser. In Chapter 04, Cmd+Enter or Ctrl+Enter sends.

The live core

Chapters 03 and 04 carry the proof. Spend most of the session there. Move through 00 to 02 briskly and label them illustrative.

Chapter 04 agent examples

  • Compare AI risk disclosures across AAPL, MSFT, GOOGL and META, what do they agree on, where do they differ?
  • Which financial-sector filings flag commercial real estate exposure as a material risk?
  • What climate-transition risks does the Energy sector disclose in its 10-Ks?
  • Across the S&P 500, which sector has the most filings citing supply-chain disruption?
  • Show me three healthcare 10-Ks that talk about generative AI in clinical workflows.

In the UI the first example joins its two clauses with a dash instead of the comma shown here. Click the example rather than typing it.

Likely questions
QuestionAccurate answer
Which model is the agent using?NVIDIA Nemotron 3.5 Lightning on vLLM on the DGX Spark, through the Kibana connector finance-ollama-llm. The config card reads the model name from the backend.
How are the filings embedded?On the kit, with Jina Embeddings v5 Omni at 768 dimensions, cosine HNSW, on the DGX Spark. Jina is part of Elastic.
What tools does the agent have?Three ES|QL tools: finance.company_disclosures, finance.compare_companies, finance.sector_breakdown. Plus seven platform tools such as search, execute_esql and generate_esql. Instructions cap it at six tool calls and require ticker and accession citations.
How many filings?Quote the count from pre-show check 8. The "503" and "93,541 chunks" on screen are static text.
Can it hallucinate?The answer is model output and should be checked. The agent retrieves with ES|QL over the index and cites ticker and accession, so every claim can be opened in Kibana.
Was the GPU race real? What is the TCO?The race is a simulation and the cost figures are illustrative models. Offer a follow-up with published GPU indexing material and a cost model built on their volumes.
Is the workflow running?No. It is an example definition shown as YAML.
Does this need the internet?Not for search or the agent: Jina v5 Omni and Nemotron 3.5 Lightning run on the DGX Spark. Chapter 05 links do.
04 · SEC FindingsFailure recovery and reset
Failure recovery per step

What breaks, and what to do on stage.

StepSymptomRecovery on stage
01 SpeedRace does not startPress Reset, then Start Race. If it still fails, move on; the chapter carries no proof.
03 Interface502 "Query embed failed"The backend cannot reach Jina v5 Omni on :8081. Skip to Chapter 04, which does not use the backend embed path. After the session, check GET :8081/health (runbook 02).
03 InterfaceSector chips missing or an errorThe sectors call failed against ES. Run a search without a sector filter. If search also fails, move to Kibana Discover.
03 InterfaceKibana buttons open a blank or error pageKibana or its data view is not ready. Stay in the app.
04 AgenticNo response for a long timeThe call has no read timeout. Press "Reset conversation", reload, and send a shorter example. Check the model with the warm-up command afterwards.
04 AgenticError or malformed eventsAgent Builder API or connector error. Open Agent Builder in Kibana and run the same question there if it works; otherwise close on Chapter 03.
WorkflowsLink clicked, 404"This workflow is an example and is not deployed here." Press Back.
05 The StackLink clicked, no page"That link needs the internet, which this kit does not have." Press Back.
Reset

Between audiences

  1. In Chapter 04, press "Reset conversation".
  2. If the Chapter 01 race ran, press Reset on that chapter.
  3. Press Esc to return to the chooser and reload the browser tab.
  4. Warm the model again if the next session is more than a few minutes away.
