Multimodal + Need-to-Know. Same question, different clearance.

Presenter runbook for Search by Image and Need-to-Know, with a note on scenes not yet merged.

Suggested length 10 to 15 minutes Status as of 13 Nov 2026 Code basis: commit 5114c3a
Audience and outcome

For intelligence and defense audiences, and any team that handles documents under need-to-know rules.

They leave knowing that one local embedding model handles text and images, that hybrid retrieval and a grounded LLM answer can be scoped to each analyst's clearance, and how this demo enforces that scope.

The story in three sentences

Search by Image shows that one local embedding model places words and pictures in the same vector space.

In Need-to-Know, every research document carries a classification, compartments and caveats, and every query carries the analyst's clearance.

The same question returns different documents, figures and answers depending on who asks.

Likely questions
QuestionAccurate answer
Is this Elasticsearch document level security?No. The application builds a filter from the analyst's clearance and adds it to every query, facet, figure lookup and answer retrieval. No Elasticsearch roles are configured. Elasticsearch supports document level security natively through roles, and a production design would enforce access there.
Could a user bypass it?In this demo, yes: anyone with Elasticsearch credentials sees every document, and the demo frontend has no login. That is why production would enforce access in Elasticsearch roles.
Is this classified data?No. The documents are public research papers. The markings are synthetic and assigned deterministically from each paper's id: about 40 % U, 25 % CUI, 15 % C, 13 % S, 7 % TS, with compartments only on S and TS.
How are compartments enforced?The analyst must hold every compartment on the document. The query uses a terms_set match with the document's compartment count as the minimum. NOFORN documents are excluded unless the analyst is NOFORN-cleared.
Does the model see restricted text?No. Retrieval runs under the filter before the model is called, and only the top passages (up to 1,200 characters each) reach it. Its instructions forbid outside knowledge. With no cleared sources it returns a fixed "no documents" reply.
Which embedding model?Jina Embeddings v5 Omni, served locally on the DGX Spark. Jina is part of Elastic. Search by Image uses 768-dimension vectors through an Elasticsearch inference endpoint. Need-to-Know uses 1024-dimension vectors in a bbq_hnsw index.
How many documents?Quote the index counts recorded in the pre-show check. The setup guide states 9,636 text chunks and 198 image records; that is documentation, not a live count.
05 · Multimodal + Need-to-KnowRecovery, reset and what is next
Failure recovery per step

What breaks, and what to do on stage.

StepSymptomRecovery on stage
Search by ImageError or no resultsThe Jina server or the inference endpoint is down. Move to Need-to-Know if /health answers; otherwise restart the server after the session.
Need-to-KnowSearch errors for every personaBackend cannot reach ES (runbook 02, K1, K2) or the Jina server. Explain the clearance model from the persona cards and offer a rerun.
Need-to-KnowAnswer panel spins for a long timeThe model call has a 120 s timeout. Continue narrating the hits and figures, which arrive independently.
Need-to-Know"No documents in your accessible corpus match this question"This is the correct canned reply when the persona has no cleared sources. Use it as a proof point, then switch to a higher clearance.
Need-to-KnowFigure strip or PDF links 404Media path mismatch. Skip figures; the text results remain valid.
Need-to-KnowResults look weak for a questionQueries are embedded as passages in this build. Use the built-in sample queries.

Reset

Press "Exit to chooser" or Esc. At the start of the next run, select Public User before the first question. Reload the browser tab between audiences.

Coming next · Not merged

A local work-in-progress build of this adventure exists on a development machine. It is behind the shared branch, is not on the kit, and must not be demonstrated or promised as shipped.

  • New scenes. "Vector Search" (retrieval by meaning) and "AI Analyst" (grounded answers) replace the current navigation. Search by Image is dropped from navigation.
  • New shell. A header with a shared "Signed in as" persona bar, a shared corpus meter and a light theme in Elastic Blue. The meter's default total is 208 papers, which conflicts with 509 elsewhere.
  • New backend options. API-key auth, an option to embed through an in-cluster inference endpoint, and an option to answer through a cloud-hosted model endpoint, to run the adventure against Elastic Cloud. That cloud option does not apply to a disconnected kit.
  • Merge risk. The work-in-progress config still uses raw IP defaults and will conflict with the .ddil change.
